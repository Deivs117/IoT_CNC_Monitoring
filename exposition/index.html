Sección 01

Caso de Uso: CNC para Manufactura de PCBs

La fresadora CNC genera variaciones de temperatura, humedad y vibración que afectan directamente la calidad del proceso. La identificación visual del tipo de PCB determina la ruta de manufactura. El sistema monitorea ambos en tiempo real.

🌡️
Temperatura
Rango operativo: 15°C – 45°C
El exceso de temperatura degrada el sustrato FR4 y provoca deformación de pistas. Por debajo del límite, el dieléctrico cambia su constante, afectando impedancias controladas.
💧
Humedad
Rango operativo: 20% – 80%
Alta humedad aumenta la resistencia del sustrato y promueve cortocircuitos. Baja humedad genera electrostática que puede dañar componentes sensibles.
📳
Vibración
MPU-6050 + MLP int8 en Edge
Vibraciones anómalas rompen fresas, desalinean el material o causan marcas de resonancia. El modelo Edge clasifica: normal, vibración leve y anomalía severa.
📷
Visión PCB
FOMO + MobileNetV2 en ESP32-CAM
Identificar el tipo de PCB en bancada activa la ruta de manufactura correcta y bloquea el inicio de proceso cuando la bancada está vacía.

Sección 03

Metodología Implementada

Cada paso del procedimiento del profesor está cubierto. Haz clic en cada ítem para ver el detalle técnico.

Determinación del caso de uso y sensores

Temperatura Humedad Vibración Clasificación imagen
▾

Caso: fresadora CNC para manufactura de PCBs. Se monitorean temperatura y humedad (DHT22), vibración / movimiento (MPU-6050 con acelerómetro y giroscopio), y clasificación visual del tipo de PCB (cámara OV2640 en ESP32-CAM). Los cuatro canales cumplen exactamente los cuatro tipos de variable exigidos por el profesor.

Conexión de sensores a GPIO del ESP32

DHT22 → GPIO 4 MPU-6050 → I²C SDA/SCL
▾

DHT22 conectado a GPIO4 con VCC 3.3V y GND. MPU-6050 conectado por I²C: SDA → GPIO21, SCL → GPIO22, alimentación 3.3V. Ambos sensores verificados con resistencias pull-up en las líneas de datos. Wiring documentado en el informe y en firmware/cnc_main_node/sensors.h.

Instalación de librerías necesarias

DHT sensor library MPU6050 Edge Impulse Arduino SDK PubSubClient (MQTT)
▾

Librerías instaladas en Arduino IDE: DHT sensor library (Adafruit), Adafruit_MPU6050, ArduinoJson, PubSubClient (MQTT), WiFi (built-in ESP32), y la librería .zip del proyecto Edge Impulse exportada directamente desde el dashboard de Edge Impulse.

Verificación mediante monitor serial

115200 baud Serial.print temperatura/humedad Predicciones impresas
▾

El firmware imprime en monitor serial (115200 baud) los valores crudos de temperatura, humedad, aceleración XYZ y el resultado de la inferencia del modelo Edge Impulse (clase predicha + score de confianza) antes de publicar por MQTT. Esto permite verificar in-situ sin necesitar red.

Implementación de modelos de IA

MLP 8→16→3 (vibración) FOMO MobileNetV2 (PCB) int8 quantizado Edge Impulse SDK
▾

Modelo 1: MLP tabular entrenado en Edge Impulse con 8 features (acelerómetro XYZ + temperatura + humedad). Exportado como librería Arduino (.zip). Accuracy 98.7%. Modelo 2: FOMO con MobileNetV2 0.35 para clasificar 4 clases de PCB en ESP32-CAM. Ambos modelos cuantizados int8, ejecutados completamente en Edge.

Conexión WiFi + MQTT a Azure IoT Hub

WiFi.begin() MQTTS 8883 Certificado CA Azure PubSubClient
▾

Ambos nodos conectan a WiFi con WiFi.begin(ssid, password). La conexión al broker es MQTTS (TLS 1.2, puerto 8883) usando el certificado raíz de Azure IoT Hub. El topic de publicación sigue el formato: devices/{device_id}/messages/events/. Credenciales almacenadas en config.h (no versionado).

Almacenamiento en base de datos

Cosmos DB Serverless telemetry_processor EventHub trigger
▾

Azure Function telemetry_processor se activa por trigger EventHub cuando llega telemetría al IoT Hub. Detecta automáticamente si el payload es del nodo de vibración o de la cámara. Persiste en Cosmos DB NoSQL (DB: CNCMonitor, container: Telemetry) con upsert. El documento incluye sensores, predicciones y alertas.

Visualización en Dashboard

HTML/CSS/JS estático Azure Static Web Polling GET /api/datos Temperatura · Humedad · Vibración · PCB
▾

Dashboard HTML puro desplegado como Azure Static Website. Polling cada 5 s a la Azure Function get_datos (GET /api/datos). Muestra temperatura, humedad, estado vibracional, score de anomalía, alerta activa y clasificación PCB con probabilidades por clase. El último valor válido se retiene si el dispositivo no publica.

Alarmas por Telegram a partir de IA

Telegram Bot API Umbrales + anomaly score Anti-spam cooldown 5 min
▾

La función evaluate_alert() en shared_code/alerts.py evalúa temperatura, humedad, estado vibracional y anomaly score (umbral ≥ 0.80). Si hay condición de alerta, maybe_send_telegram_alert() envía mensaje al bot con cooldown de 5 minutos para evitar spam. El campo alerts.telegram_sent se persiste en Cosmos DB.

Sección 08

Fortalezas y Conclusiones

⚡
Edge AI Real
Inferencia completamente en dispositivo. Sin latencia de red para decisiones críticas. MLP en 2 KB, FOMO en ~275 KB.
☁️
Serverless
Azure Functions + Cosmos DB Serverless. Pago por uso real. Escalado automático. Sin administración de servidores.
💰
Bajo Costo
Hardware: ESP32 (~5 USD) + ESP32-CAM (~7 USD). Cloud: tier gratuito IoT Hub + Cosmos DB Serverless. Frontend: Azure Static.
🔧
Modular
Firmware, backend y frontend completamente independientes. Nuevos sensores o nodos se integran sin cambiar el backend.
📈
Escalable
IoT Hub soporta millones de dispositivos. Cosmos DB escala horizontalmente. Functions escala en paralelo automáticamente.
🎓
Reproducible
Scripts Bash de despliegue automatizados. Deploy completo desde Azure Cloud Shell en pasos documentados.
🏭
Industrial
Ruta de manufactura PCB determinada automáticamente. Monitoreo preventivo real. Alertas accionables en producción.
🔒
Seguro
TLS 1.2 en MQTTS. Credenciales en variables de entorno. Certificado CA Azure. Secrets fuera del repositorio.
